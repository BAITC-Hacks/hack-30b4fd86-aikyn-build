# AIKYN BILD — Beeline Tariff Marketing Campaigns

Агент для маркетинговых кампаний Beeline: выбирает сегменты абонентов, целевые тарифы и каналы, чтобы увеличить суммарный ARPU с учётом стоимости контактов, бюджета и лимита охвата. История переходов задаёт начальные гипотезы, а пилоты помогают уточнять выбор. Данные синтетические.


## Быстрый запуск (Windows PowerShell)

Проверено на Python 3.14. Для запуска откройте корень репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe local_eval.py
.\.venv\Scripts\python.exe local_eval.py --runs 10
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe make_submission.py
.\.venv\Scripts\python.exe verify_pass.py
```

На других ОС используйте Python из своего виртуального окружения. Все команды запускаются из корня repo: организаторские скрипты используют относительные пути данных.

## Основной сценарий и demo

Вход: `customer_profile.csv`, справочники и история `data/change_tariff.csv`.
Действие: `Agent.act(env)` формирует гипотезы, запускает пилоты через публичный `env.run_pilot`, обновляет оценки по их наблюдаемым результатам и выбирает аудиторию, тариф и канал для кампаний. Локально пилоты используют mock-эффекты; жюри запускает агента в своей среде.
Выход: `make_submission.py` сохраняет план в `submission.csv`, а `local_eval.py` показывает мок-результат, расходы и охват.

Показать жюри: запуск `local_eval.py`, чистый результат и соблюдение лимитов, затем `submission.csv` и повторную генерацию. `verify_pass.py` печатает независимый JSON-отчёт о сырых кампаниях и повторяемости CSV.

## Подход

1. Исторические относительные изменения ARPU агрегируются медианой по исходному тарифу, ARPU-сегменту и целевому тарифу. Малые группы получают меньший вес. История определяет порядок разведки, а не скрытые эффекты.
2. До 12 первых пилотов исследуют разные сегменты. Оставшиеся пилоты уточняют перспективные варианты с учётом неопределённости; до трёх измерений на гипотезу.
3. Решения используют среднее из пилотов и консервативную поправку, убывающую с числом наблюдений. Это эвристика риска, не гарантированный доверительный интервал для скрытой аудитории.
4. Первая версия сравнивает SMS с бесплатным push. Дорогие каналы пока не используются: перенос измерений на более сильный канал может быть неверным из-за насыщения конверсии.
5. Финальные сегменты не пересекаются. Планировщик резервирует деньги и контакты с учётом пилотов, не полагаясь на автоматическое обрезание оценщиком. Крупные сегменты разбиваются доступными фильтрами.
6. Если нет консервативно положительного варианта, возвращается лучший проверенный вариант через бесплатный канал (`fallback_risk`). Если пилоты недоступны, возможна одна резервная кампания по историческим данным (`pilot_unavailable_fallback`); она явно помечена как непроверенная и может дать отрицательный результат.

`agent.py` использует pandas и стандартную библиотеку Python. Локальная среда и оценщик также используют NumPy. Агент работает без LLM и API-ключей; публичный интерфейс среды — единственный источник результатов пилотов, скрытые внутренности и модель эффектов агент не читает. При отсутствии истории гипотезы выбираются детерминированно без исторического ранжирования.

## PASS и ограничения

- 1–10 валидных финальных кампаний; существующие тарифы и каналы.
- Более нуля и не более 20 пилотов, 10–200 абонентов в пилоте.
- До 5000 абонентов на кампанию, 15000 контактов и 100000 у.е. всего, включая пилоты.
- План зависит от наблюдений; `submission.csv` воспроизводится при seed=42.
- Рабочая цель времени: менее 5 минут, что также удовлетворяет 10 минутам основного условия.
- При отказе пилота агент записывает ошибку и продолжает проверять следующие гипотезы. Если не удался ни один пилот, он может вернуть помеченную непроверенную резервную кампанию по историческому приоритету, если остатки позволяют. При нулевом остатке контактов план невозможен; детали — в `docs/VALIDATION.md`.

`verify_pass.py` проверяет сырые выходы агента до sanitizing/capping оценщика, отсутствие пересечения финальных сегментов, расходы с учётом пилотов, время на 10 seed, а также повторяемость CSV при seed=42. Он печатает JSON-отчёт в консоль. Команда `python -m unittest discover -s tests -v` проверяет поведение на публичном контракте среды. `local_eval.py --runs 10` отдельно оценивает чистый результат.

Важно: поле «Кампаний» в отчёте local_eval включает пилоты. Например, 24 = 20 пилотов + 4 финальные кампании. Строки «Осталось бюджета/охвата» показывают остаток после пилотов; итоговые расходы смотрите в общей таблице результата.

## Первый локальный результат

На проверенной версии seed=42: 5 финальных кампаний, 20 пилотов, чистый мок-прирост 1222447 у.е., расходы 31488, контакты 7872. На seed 0–9: 10 из 10 результатов положительные; минимум 1247717, медиана 1602548, максимум 1730401 у.е. Округлено до целых.

Это проверка на мок-эффектах, не прогноз конкурсного балла. История относится к другой выборке. Все положительные результаты на скрытой среде гарантировать невозможно.
Эти цифры относятся к проверенной версии `agent.py`, SHA-256 которой указан в `docs/VALIDATION.md`; после изменения агента проверки и артефакты нужно пересоздать.

## Файлы и сдача

- `agent.py` — решение команды, класс Agent и метод act(env).
- `submission.csv` — воспроизводимый план, генерируется make_submission.py.
- `requirements.txt` — зависимости.
- `verify_pass.py`, `tests/test_contract.py` — независимая проверка сырых кампаний и публичного контракта.
- `validation.json` — итоговый артефакт проверки; капитан пересоздаёт его после интеграции финального `agent.py`.
- `local_eval.py`, `make_submission.py`, `environment.py`, `mock_environment.py`, `scoring_core.py`, шаблон и данные — неизменённый пакет участника.
- `PARTICIPANT_GUIDE.md` — условие из пакета. Отдельный PDF кейса содержит также рубрику 25/25/25/15/10; README и воспроизводимость дают до 25 баллов.
- `docs/` — прежние подготовительные документы, сохранены. Их упоминания Construction и старых названий не определяют текущий кейс.
